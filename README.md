# EduManage

# نظام إدارة مدرسة اللغات الخاصة — الرؤية التقنية الكاملة

> وثيقة تقنية شاملة تغطي كل جوانب المشروع من الفكرة حتى الإطلاق

---

## 1. نظرة عامة على المشروع

مشروع **نظام إدارة مدرسة اللغات** هو حل رقمي متكامل يهدف إلى رقمنة جميع العمليات اليومية لمدرسة لغات خاصة، من تسجيل التلاميذ وإدارة المدرسين وجدولة الحصص، وصولاً إلى نظام الدفع والتواصل مع الأولياء والأرشفة السنوية.

يتكون النظام من **أربعة تطبيقات** تعمل على منصتين (هاتف + حاسوب)، جميعها تتصل بنفس قاعدة البيانات المركزية.

|---------|------------|--------------|-------|

## 3. الوحدات الوظيفية الكاملة

### 3.1 إدارة المستخدمين والصلاحيات

- تسجيل الدخول بالبريد الإلكتروني أو رقم الهاتف
- نظام أدوار (Role-Based Access Control): مدير، مدرس، تلميذ، ولي
- كل دور يرى واجهة مختلفة وبيانات مختلفة
- تسجيل خروج تلقائي بعد فترة خمول

### 3.2 إدارة التلاميذ

- ملف كامل لكل تلميذ: الاسم، الصورة، تاريخ التسجيل، المستوى، اللغة المدروسة
- ربط كل تلميذ بوليه ومدرسه
- سجل تطور المستوى عبر الزمن
- إمكانية تسجيل تلميذ في أكثر من لغة أو مستوى

### 3.3 إدارة المدرسين

- ملف كامل: التخصص، اللغات التي يدرسها، نوع الراتب (ثابت أو حسب الحصص)
- عدد التلاميذ المسندين لكل مدرس
- محفظة مالية: مجموع المستحقات، المدفوع منها، الباقي
- جدول أسبوعي خاص بكل مدرس

### 3.4 الجداول والحصص

- جدول أسبوعي قابل للتعديل
- توزيع التلاميذ على الحصص والمدرسين
- إمكانية إلغاء حصة أو تأجيلها مع إشعار فوري
- دعم حصص متعددة في نفس الوقت مع مدرسين مختلفين

### 3.5 الحضور والغياب

- تسجيل الحضور اليومي من طرف المدرس
- إشعار فوري للولي عند تسجيل غياب الابن
- إحصائيات الغياب الشهرية والسنوية
- تقرير حضور قابل للطباعة

### 3.6 نظام الدفع الكامل

**دفعات التلاميذ:**
- دفع شهري أو لكل حصة أو مسبق
- تسجيل كل دفعة مع التاريخ والمبلغ وطريقة الدفع
- إشعار تلقائي عند تأخر الدفع
- وصل دفع PDF يحتوي: الاسم، التاريخ، المبلغ، الخدمة، ختم المدرسة

**مستحقات المدرسين:**
- حساب تلقائي حسب عدد الحصص أو الراتب الثابت
- وصل راتب PDF عند الصرف
- سجل كامل للمدفوعات السابقة

**التقارير المالية:**
- إجمالي الدخل الشهري
- إجمالي المصاريف (رواتب المدرسين)
- صافي الأرباح
- تقرير PDF شهري تلقائي لصاحب المدرسة

### 3.7 نظام الإشعارات

| نوع الإشعار | المرسِل | المستقبِل | التوقيت |
|------------|---------|----------|---------|
| غياب التلميذ | تلقائي | الولي | فوري |
| يوم مغلق | المدير | الجميع | فوري + تذكير صباحي |
| تغيير في البرنامج | المدير أو المدرس | تلاميذ الحصة + أوليائهم | فوري |
| إلغاء حصة | المدرس أو المدير | تلاميذ الحصة + أوليائهم | فوري |
| دفعة متأخرة | تلقائي | الولي | أول كل شهر |
| ملاحظة من المدرس | المدرس | الولي + التلميذ | فوري |
| راتب مستحق | تلقائي | المدرس | عند الاستحقاق |
| تقييم جديد | المدرس | التلميذ + الولي | فوري |
| تذكير حصة | تلقائي | التلميذ | قبل ساعة |

### 3.8 التقييمات والمتابعة الأكاديمية

- تقييم شهري لكل تلميذ من طرف مدرسه
- مستويات: مبتدئ، متوسط، متقدم
- منحنى تطور التلميذ عبر الزمن
- ملاحظات المدرس مرئية للولي والتلميذ

### 3.9 الأرشفة السنوية

في نهاية كل سنة دراسية يتم:

1. تصدير كل البيانات إلى ملفات JSON/CSV
2. ضغطها في ملف ZIP واحد
3. رفعها تلقائياً إلى Google Drive
4. تفريغ Supabase تماماً للسنة الجديدة
5. إمكانية استرجاع أي سنة سابقة في أي وقت

**هيكل الأرشيف في Google Drive:**

```
📁 أرشيف المدرسة/
  📁 2024-2025/
    📄 students.json
    📄 teachers.json
    📄 attendance.json
    📄 payments.json
    📄 evaluations.json
    📄 notifications.json
    📁 receipts/
      📄 receipt_001.pdf
      📄 receipt_002.pdf
```

## 4. البنية التقنية الكاملة

### 4.1 المكدس التقني (Tech Stack)

| الطبقة | التقنية | السبب |
|--------|---------|-------|
| التطبيقات (هاتف + حاسوب) | Flutter | كود واحد لكل المنصات |
| قاعدة البيانات | Supabase (PostgreSQL) | مجاني، قوي، API جاهز |
| المصادقة | Supabase Auth | مدمج مع قاعدة البيانات |
| منطق الخادم | Supabase Edge Functions | مجاني، بدون سيرفر منفصل |
| تحديث فوري | Supabase Realtime | استقبال التحديثات لحظياً |
| الإشعارات Push | Firebase Cloud Messaging | مجاني بلا حد |
| وصولات PDF | flutter_pdf + printing | مدمج في Flutter |
| الأرشيف السنوي | Google Drive API | 15GB مجاني |
| النشر Android | Google Play Store | 25$ مرة واحدة |
| النشر iOS | Apple App Store | 99$/سنة |

### 4.2 هيكل قاعدة البيانات

```sql
-- المستخدمون وأدوارهم
users (id, name, email, phone, role, avatar_url, created_at)

-- المدرسون
teachers (id, user_id, specialty, languages[], salary_type, salary_amount)

-- التلاميذ
students (id, name, level, language, parent_id, enrollment_date, avatar_url)

-- الأولياء
parents (id, user_id, phone, address)

-- ربط الأولياء بأبنائهم
parent_students (parent_id, student_id)

-- الحصص والجداول
classes (id, teacher_id, language, level, schedule, room, max_students)

-- تسجيل التلاميذ في الحصص
student_classes (student_id, class_id, enrollment_date, status)

-- الحضور اليومي
attendance (id, student_id, class_id, date, status, note)

-- دفعات التلاميذ
payments_students (id, student_id, amount, date, status, method, receipt_url)

-- مستحقات المدرسين
payments_teachers (id, teacher_id, amount, date, status, receipt_url)

-- التقييمات الأكاديمية
evaluations (id, student_id, teacher_id, score, level, comment, date)

-- الإشعارات
notifications (id, type, title, body, target, target_id, sent_at, is_read, scheduled_at)

-- رموز الإشعارات Push
fcm_tokens (id, user_id, token, platform, updated_at)

-- سجل الأرشيف
archive_history (id, year, file_url, size_mb, archived_at, restored_at)
```

### 4.3 كيف يعمل إرسال الإشعار تقنياً

```
المدير يضغط "يوم مغلق"
        ↓
Flutter يرسل طلب لـ Supabase Edge Function
        ↓
Edge Function تجلب كل FCM tokens من قاعدة البيانات
        ↓
ترسل طلب جماعي لـ Firebase FCM
        ↓
FCM يوصل الإشعار لكل الهواتف فوراً
        ↓
يُسجَّل الإشعار في جدول notifications
```

### 4.4 كيف يعمل الأرشيف السنوي تقنياً

```
نهاية السنة الدراسية
        ↓
Supabase Edge Function تصدر كل الجداول إلى JSON
        ↓
Flutter تضغط الملفات في ZIP
        ↓
رفع ZIP إلى Google Drive عبر API
        ↓
تسجيل رابط الأرشيف في archive_history
        ↓
حذف كل بيانات السنة من Supabase
        ↓
Supabase جاهزة للسنة الجديدة بنسبة 0%
```

## 6. تقنيات تقليل الاستهلاك

### 6.1 Cache المحلي في Flutter

بدل إرسال طلب لـ Supabase في كل مرة يفتح المستخدم التطبيق، يتم:
- تخزين البيانات محلياً على الهاتف
- تجديدها كل 10 دقائق فقط أو عند تغيير حقيقي
- **النتيجة: توفير ~60% من الطلبات**

### 6.2 Supabase Realtime بدل Polling

بدل أن يسأل التطبيق كل دقيقة "هل هناك تحديث؟"، يستقبل التحديث تلقائياً فقط عند حدوث تغيير.
- **النتيجة: توفير ~40% من الطلبات**

### 6.3 تجميع الطلبات

بدل إرسال 5 طلبات منفصلة عند فتح التطبيق (بيانات التلميذ + جدوله + دفعاته + تقييماته + غياباته)، يُرسل طلب SQL واحد يجلب كل شيء دفعة واحدة.
- **النتيجة: توفير ~70% من الطلبات**

## 8. العقبات والتحديات التقنية

### 8.1 العقبات المتوقعة وحلولها

| التحدي | الوصف | الحل |
|--------|-------|------|
| **اتصال الإنترنت** | التطبيق يتوقف إذا انقطع النت | وضع Offline: تخزين البيانات محلياً ومزامنتها لاحقاً |
| **الإشعارات على iOS** | Apple تفرض قيوداً صارمة على الإشعارات | استخدام APNs عبر Firebase + اشتراك Apple 99$/سنة |
| **حجم ملف Flutter Desktop** | التطبيق قد يكون كبير الحجم | استخدام lazy loading وتقليل المكتبات |
| **تزامن البيانات** | إذا عدّل شخصان نفس السجل في نفس الوقت | Supabase يحل هذا بـ Row-Level Security + Optimistic UI |
| **أمان البيانات** | البيانات حساسة (معلومات الأطفال والمدفوعات) | Row-Level Security في Supabase: كل مستخدم يرى بياناته فقط |
| **حد Supabase عند النمو** | عند 500+ تلميذ ينتهي المجاني | الأرشفة السنوية تحل هذا جزئياً، والخطة المدفوعة 25$/شهر |
| **الطباعة المباشرة** | بعض الطابعات لا تدعم Flutter | استخدام مكتبة printing التي تدعم معظم الطابعات |
| **الأرشيف الكبير** | إذا كانت الصور كثيرة قد يكبر الأرشيف | ضغط الصور قبل التخزين + Google Drive 15GB يكفي |
| **تحديثات Flutter** | التطبيق قد يتطلب تحديثاً دورياً | CI/CD تلقائي عبر GitHub Actions مجاناً |
| **أداء التطبيق** | عند كثرة البيانات قد يبطؤ | Pagination: تحميل البيانات على دفعات وليس كلها مرة واحدة |

### 8.2 تحديات الإشعارات تحديداً

| المشكلة | التفصيل | الحل |
|---------|---------|------|
| إشعار "يوم مغلق" لا يصل للجميع | بعض الهواتف تحجب الإشعارات | إضافة رسالة داخل التطبيق + SMS كخيار احتياطي |
| الإشعارات المجدولة | Supabase Edge Functions لا تدعم cron مجاناً بشكل مثالي | استخدام pg_cron في Supabase (متاح مجاناً) |
| فقدان FCM Token | عند إعادة تثبيت التطبيق يتغير الرمز | تجديد الرمز تلقائياً عند كل تسجيل دخول |

### 8.3 تحديات الأرشفة

| المشكلة | الحل |
|---------|------|
| انقطاع الإنترنت أثناء الأرشفة | استئناف الرفع من حيث توقف (Resumable Upload في Google Drive) |
| نسيان الأرشفة | تذكير تلقائي لصاحب المدرسة قبل نهاية السنة بأسبوعين |
| استرجاع بطيء | واجهة بسيطة في التطبيق تعرض قائمة السنوات وتتيح تنزيل أي سنة |
